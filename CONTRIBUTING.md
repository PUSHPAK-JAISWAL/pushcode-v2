# Getting Started

## 1. Fork the Repository

Click the **Fork** button on GitHub.

---

## 2. Clone Your Fork

```bash
git clone https://github.com/<your-username>/<repository>.git

cd <repository>
```

---

## 3. Create a New Branch

Use a descriptive branch name.

```bash
git checkout -b feature/add-dark-mode
```

Examples:

```text
feature/login-page
feature/new-api

bugfix/fix-auth

docs/update-readme

refactor/service-layer

test/add-unit-tests
```

---

## 4. Install Dependencies

Follow the project's README for installation instructions.

---

## 5. Make Your Changes

Please ensure that your code:

* Follows the existing coding style
* Is clean and readable
* Includes comments where necessary
* Does not introduce unnecessary dependencies

---

## 6. Test Your Changes

Before submitting your work:

* Build the project successfully
* Run all tests
* Verify new functionality
* Ensure no existing functionality is broken

---

## 7. Commit Your Changes

Use meaningful commit messages.

Good examples:

```text
feat: add user profile endpoint

fix: resolve JWT validation issue

docs: update installation guide

refactor: simplify authentication logic

test: add unit tests for user service
```

Avoid messages like:

```text
update

changes

fix

new code
```

---

## 8. Push Your Branch

```bash
git push origin feature/add-dark-mode
```

---

## 9. Open a Pull Request

When creating a Pull Request, include:

* Description of the changes
* Reason for the changes
* Screenshots (if applicable)
* Related issue number (if any)

Example:

```text
## Description

Added dark mode support for the dashboard.

## Related Issue

Fixes #12

## Screenshots

(Attach screenshots here)
```

# Pull Request Guidelines

Before submitting a Pull Request:

* Keep changes focused.
* Avoid unrelated modifications.
* Update documentation if needed.
* Ensure all tests pass.
* Resolve merge conflicts.
* Keep commits clean and meaningful.

# Coding Standards

Please follow these general guidelines:

* Write readable code.
* Keep functions small and focused.
* Use meaningful variable names.
* Avoid duplicate code.
* Remove unused code.
* Keep files organized.
* Write comments only when necessary.

# Branch Naming Convention

Recommended branch prefixes:

```text
feature/

bugfix/

hotfix/

docs/

refactor/

test/

chore/
```

Examples:

```text
feature/payment-api

bugfix/login-error

docs/update-readme

refactor/auth-service

test/user-controller

chore/update-dependencies
```

# Commit Message Convention

This project follows a simplified Conventional Commits format.

Examples:

```text
feat: add search functionality

fix: resolve memory leak

docs: update API documentation

style: format code

refactor: simplify service layer

test: add integration tests

build: update Maven dependencies

ci: update GitHub Actions workflow

chore: clean up project structure
```
